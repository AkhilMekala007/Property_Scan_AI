2 · Architecture

Three inputs, one common format, one shared engine

Each tier has a small adapter that converts its files into a FrameSet. Everything after that is shared code. Thinner input carries a larger uncertainty, so intervals widen on their own.

LiDAR adapter

Sensor depth + confidence + ARKit poses. Small σ.

Video adapter

Keyframes → metric depth model + COLMAP poses. Medium σ.

Photo adapter

Per-room photos → metric depth model, no global poses. Large σ.

5 · Model stack

Small pretrained models where sensors fall short, maths everywhere else

All CPU-friendly and offline. Weights are downloaded by a setup script, never committed. No LLMs or cloud APIs in v1.

Depth Anything V2 · Metric Indoor S

videophoto

Distance in metres for every pixel of an ordinary photo. Stands in for the LiDAR sensor.

SegFormer · ADE20K

all tiers

Labels wall, floor, ceiling, door, window and mirror, so furniture doesn't distort the room.

pycolmap

video

Camera motion from video frames (structure from motion). Scale comes from the depth model.

OWLv2 + SAM 2-tiny

damage

Finds "water stain" or "crack" from a text prompt, then outlines the exact pixels.

Open3D

geometry

Plane fitting (RANSAC), surface fusion (TSDF), alignment (ICP), pose graph for drift.

pydantic · svgwrite

output

Validated JSON with a generated published schema, and the rendered SVG floor plan.

6 · Robustness

Every problem lowers confidence or gets refused

The brief caps the total score for confident wrong answers on thin input, so we never produce one.

→Moving too fast, blurry frames
→Ceiling never captured
→Too few or non-overlapping photos
→Mirrors, glass, wet-look surfaces
→Low light, people walking through
→Drift on long walks

QC + uncertainty

Detect, drop bad data, raise σ
Lower confidence: wider interval and a warning in the JSON
Clear refusal: null with a reason, e.g. "ceiling not seen"
Never: a precise-looking number that's wrong
7 · If a model underperforms

Measure each model, then climb the ladder only as far as needed

LiDAR captures record RGB, true depth and true poses together, which gives free ground truth for the depth and pose models.

Step 1

Zero-shot baseline

Pretrained weights as-is, scored per component by the harness.

Step 2

Light calibration

2–5 parameter corrections, validated on a held-out capture.

Step 3

Fallback ladder

Swap or augment the model. Time-boxed to 1–2 hours each.

Step 4

Widen and document

Honest intervals, listed as a known failure. Fine-tuning becomes the next step.

10 · Decisions so far

What we've locked in

Stock apps + protocolNo Mac, so no iOS build. Stray Scanner matches the sample data.
Tier auto-detectedFrom the files, never asked. Data wins over claims.
Warn, don't blockUnsupported devices still run, with wider intervals.
No property typeThe system finds the rooms. Photo folders are named per room.
CLI onlyOne command per capture, as the brief asks.
Offline, no LLMRespects "no infra" and keeps the live walk-in safe.
Pretrained firstThen light calibration. Fine-tune only if a gate still fails.
Geometry decidesModel outputs are votes; planes and multiple views settle them.
